## 二、识别决策规则

| 检测优先级 | 匹配特征 | 判定实现 | 额外能力触发 |
| :--- | :--- | :--- | :--- |
| **1** | `app_name` 包含 `napcat` | `NapCat` | 启用 `nc_get_user_status` 在线状态获取 |
| **2** | `app_name` 包含 `lagrange` 或存在 `nt_protocol` | `Lagrange` | 适配 Lagrange 特有字段与时间格式 |
| **3** | `app_name` 包含 `llonebot` / `llbot` / `luckylillia` | `LLBot` | 适配 LLBot 特有数据格式 |
| **Fallback** | 接口报错或无法识别的端 | `NapCat` | 降级使用兼容性最广的默认方案 |

## 三、性能与缓存设计

1. **单实例生命周期只嗅探一次**：检测结果以 `bot.selfId` 为 Key 存入内存 `Map`，耗时仅几毫秒，后续指令调用 0 额外网络开销；
2. **连接状态联动失效**：监听 Koishi 的 `bot-status-updated` 事件，Bot 掉线或重连时自动清理缓存；
3. **完全向后兼容**：若用户在配置中手动指定具体平台，直接遵循手动选择，不触发任何探测逻辑。
